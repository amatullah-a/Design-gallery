# Component Audit Prompts — Usage Guide

## Purpose
Use these files to audit individual UI components in a website or application prototype. The focus is on component-level consistency and adherence to documented component guidance, rather than a broad visual-design or UX audit.

## Files in This Folder

### `Component_Specific_Visual_Audit_Prompt_Updated_v3.1.txt` — Component Audit Instructions
Use this prompt to inspect components present in the prototype, such as cards, buttons, lists, typography, and iconography. Record specific component-level issues and actionable improvements supported by the prototype.

### `Skills_File_Visual_Component_Rules_Updated.txt` — Component Rules Reference
Use this document as the reference for the relevant skills, principles, and component specifications. Check the applicable guidance when evaluating the prototype so findings are more consistent and grounded in the stated criteria.

## How to Use These Files
1. Provide the prototype link, screenshots, or design files to be evaluated.
2. Attach `Component_Specific_Visual_Audit_Prompt_Updated_v3.1.txt` as the primary audit instruction.
3. Attach `Skills_File_Visual_Component_Rules_Updated.txt` as the supporting reference.
4. Ask for a component-level audit of the supplied prototype, following the prompt and consulting the rules where relevant.
5. Review the findings to ensure each issue is tied to an observed component or a relevant documented criterion.

## Expected Output
A focused report identifying component-level inconsistencies and actionable improvements supported by the prototype and the reference rules.

## Important
Keep the audit focused on the components themselves. Do not turn it into a general website UI, visual-design, or UX audit unless the selected instructions explicitly require that broader scope.
