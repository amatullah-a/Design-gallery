1. Unified design system evaluation
Design evaluation/assessment prompts

Objective: Check if the entire UI follows one consistent design system across all screens and components, but do not provide a solution redesign.

Prompt 1:
Unified Design System Evaluation

Act as a senior UI/UX design auditor.
Evaluate the website only from a system consistency perspective. Do not redesign anything.
Focus only on:
• Consistency of components (buttons, forms, tables)
• Consistent styles (border radius, shadows, icons)
• Interaction states (hover, active, disabled)
• Reuse of patterns across screens

Identify:
• System-level inconsistencies
• Pattern mismatches
• Missing or broken design rules
Cross-page consistency of components and patterns on the live site.


Output Requirement (Strict)
• Output must be a downloadable HTML file only.
• Follow the provided HTML report structure exactly.
• Use proper HTML tags for tables, sections, and headings.
• No additional text outside the HTML.


Output Format (Strict)
• Structured table with:

| # | Category | Sub-Category | Rating (1–10) | Key Issue | Impact | Area of Action | Real-World Example | URL | Critical (Yes/No) |

Rules
• Each major section must start with a section header row:
--- SECTION NAME ---
• No design system docs unless unavoidable
• Keep findings specific, not generic



2. UI audit
Objective: Check overall visual quality and cleanliness of the UI., but do not provide a solution redesign.

Prompt 2:


Act as a UI auditor.
Evaluate the visual quality of the wireframe. Do not redesign.
Focus only on:
• Typography usage (sizes, weights, hierarchy)
• Visual consistency of UI elements
• Alignment of elements (not grid system, just visual neatness)
• Button and element clarity

Identify:
• Visual inconsistencies
• Poor readability
• Misaligned or cluttered UI
Visual issues that appear only on mobile / different breakpoints.

Do not evaluate UX flows or deep layout structure.

WF correction prompt
Wireframe correction prompt:

Analyze the attached report and evaluate whether any structural, layout, hierarchy, or UI consistency updates are required in the current wireframe. If improvements are necessary, implement the revisions directly within the wireframe. Do not introduce or modify the existing color palette under any circumstances.




Labels, wording, typography, readability,
Objective: Assess wireframe labels, wording, typography, readability, consistency, and grammar quality.

Evaluate the entire wireframe focusing on labels, wording, typography, and text quality across the interface.
Assess the following:
1. Label clarity – Are field names, section titles, and table headers clear and understandable?
2. Terminology consistency – Are similar terms and actions used consistently across the interface?
3. Typography hierarchy – Do headings, labels, and table headers follow a clear visual hierarchy?
4. Readability – Are font sizes, spacing, and text density easy to read and scan?
5. Button and action labels – Do buttons clearly communicate the intended action?
6. Grammar and spelling – Identify any typos, incorrect capitalization, or grammatical issues.

Provide the results in a table format with:
| Category | Element / Label | Issue | Severity (Low / Medium / High) | Recommendation |
Keep the evaluation strictly analytical and concise, without redesigning the interface.
